## Findings
- [settled] F1: current UI is single-column, full-page nav (back-chevron header, bottom sheets, tree/diff as routes, transcript max-w-3xl); desktop-aware only in split diffs ≥1024px and Enter-to-send on fine pointers; no global shortcuts — acknowledged
- [settled] F2: server accepts http://localhost:4180 on the Mac with no config and runs several agents concurrently; UI shows one at a time — acknowledged
- [settled] F3: open-agents list = GET /api/agents polled every 10 s (status, isStreaming, attention none|finished|failed|input); no global event stream, only per-agent SSE — acknowledged
- [settled] F4: switching agents tears down store + SSE and refetches a full snapshot; server allows unlimited SSE subscribers per agent; push fires on every finish/fail/input — acknowledged
- [settled] F5: push needs no FCM config (web-push + VAPID). Likely causes: SW suppresses notifications while any pi-code tab is focused (sw.ts:70-78); SW only registers in prod builds; localhost vs tailnet are separate origins → separate subscriptions — acknowledged
- [settled] F6: GET /api/sessions returns all sessions sorted by updatedAt = last entry timestamp (agent or human), cached, no pagination (54 local files); AgentInfo has no activity timestamp; git branch only via per-running-agent endpoint, spawned fresh each call — acknowledged
- [settled] F7: localhost:4180 is HTTP/1.1 (tailnet is HTTP/2, verified with curl); Chrome caps HTTP/1.1 at 6 connections per host across all tabs, each SSE holds one — acknowledged
- [settled] F8: pi session files don't record a git branch (header is only id/cwd/timestamp) — acknowledged
- [settled] F9: browsers only speak HTTP/2 over TLS (no h2c); tailnet URL gives it for free, localhost would need local TLS — acknowledged
- [settled] F10: pi extensions can persist non-context data into the session file (pi.appendEntry); the pi-code extension is only loaded by pi-code (--extension), not the TUI — acknowledged
- [settled] F11: with one multiplexed stream per tab, F7's connection limit no longer bites, so localhost would also work — acknowledged
- [settled] F12: no separate "unread" state; attention=finished until the client acks (POST /agents/:id/ack) plays that role — acknowledged
- [settled] F13: a single stream must know which conversations the tab opened — via URL list (reconnect once per newly opened one) or connection id + subscribe POSTs (stateful server) — acknowledged
- [settled] F14: streams resume via EventSource's automatic Last-Event-ID = per-agent seq (sse.ts:18-52); a multiplexed stream has several cursors but one Last-Event-ID — acknowledged
- [settled] F15: nothing is registered: the catalog scans pi's own session files (~/.pi/agent/sessions, TUI sessions included); folders derive from session cwds; per session: name, firstMessage, cwd, timestamps; transcripts aren't indexed — acknowledged
- [settled] F16: iPad widths — portrait 744–1024, landscape 1080–1366 (10.2" iPad at 1080, flagged in cross-review); largest phone landscape ≈932 — acknowledged
- [settled] F17: EventSource only issues bodiless GETs; the per-event id size, not URL length, is the pressure point — acknowledged
- [settled] F18: no idle policy existed — live pi processes stayed open until closed or server stop/restart — acknowledged

## Live stream
- [settled] One multiplexed SSE stream per tab, desktop and phone; carries sidebar status and catalog changes, plus full events for conversations opened in this tab — user
- [settled] The stream URL lists opened conversations with cursors; opening a new one reconnects the stream; switching between opened ones doesn't — user, cleanest of F13's options
- [settled] Cursor list encoded as agentId:seq pairs, so auto-reconnect resumes every conversation — user; agent agrees; self-describing at the cost of larger ids
- [settled] Server watches the sessions dir and pushes catalog changes through the stream (every event, trailing throttle, 500 ms max wait) — user; covers TUI-created sessions
- [settled] Wire shape: GET /api/stream?open=<id>:<seq>,…; without open, status and catalog only; unknown ids and unparseable pairs ignored; every frame except ping carries the cursor list as id: — drafting choice, accepted
- [settled] resync is a stream frame; the client re-runs the open path for that store (snapshot, hydrate, reconnect), excluding it from reconnect URLs meanwhile; no buffering — drafting choice, accepted after simplification pass
- [settled] Every hydrate reconnects the stream; no reconnect coalescing — simplification pass
- [settled] Catalog changes sent as full 7-day windows (no ownedBy); GET /api/sessions stays all-ages with q; catalog frames invalidate sessions/projects queries — drafting choice, accepted
- [settled] Branches travel in branch frames keyed by cwd; one git-dir watch per cwd with a live agent; detached HEAD shows a 7-char commit — drafting choice, accepted
- [settled] Missing <agentDir>/sessions at startup: warning, no watcher — accepted limitation; agent dir is read-only to pi-code
- [settled] GET /api/agents stays for harness and scripts; the web client doesn't poll it — drafting choice, accepted
- [settled] Per-agent SSE endpoint removed — user; its only consumers (web client, test harness, smoke script, tests) move to the multiplexed stream

## Desktop chrome
- [settled] GET /snapshot has no side effects; the client acks the conversation on screen — user accepted drafting choice #7: background re-snapshots (resync, reconnect) would otherwise clear unseen attention marks
- [settled] Live = pi process running; exited agents (pi died) are not live: no mark, no close action, no folder branch, reopening restarts them, idle sweep removes leftovers — user, vetoing drafting choice #14
- [settled] Desktop has no back chevron; settings live in the sidebar footer; sidebar toggle in the shell chrome on every route — user accepted drafting choice #13

## Lifecycle
- [settled] Idle policy: an hourly sweep closes a conversation once its last activity (agent or human) is ≥ 7 days old; skips streaming ones, includes exited ones, ignores close errors — user; sweep details accepted
- [settled] Activity = later of the session's updatedAt and the agent's startedAt; no separate activity tracking — simplification pass; limitation: dialog answers and trust write no session entry, so they don't reset the clock
